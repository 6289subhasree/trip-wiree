# ADR 0002: Authenticate demo envelopes with HMAC-SHA256

**Status:** Superseded by [ADR 0005](0005-per-agent-keys-protocol-v2.md) (single shared secret replaced by per-agent keys).

## Context

TripWire needs an inspectable message-integrity and shared-secret authentication mechanism that is available in Python's standard library. The demo has one trusted Sentinel and one trusted Relay in the same process.

## Decision

Sign a canonical JSON representation of each envelope with HMAC-SHA256. Include version, UUID message ID, sender, creation timestamp, and payload in the signed data. Verify with `hmac.compare_digest`.

## Trade-offs

HMAC is small, well-known, and requires no dependency. Both sides need the same secret, so it does not provide non-repudiation or independent public-key identity. It does not encrypt content. Canonicalization rules become part of the protocol contract.

## Consequences

The tests can exercise tampering and validation deterministically. The embedded demo secret is intentionally public and must never be treated as production key management. A production system would require a reviewed key lifecycle and possibly a different identity/transport model.
